# Tonight Web Browsing

Created October 3, 2026. Scope: T04 movie/TV/library galleries, submitted search, and accessible collection browsing in [Tonight implementation](../branding/TONIGHT_IMPLEMENTATION_PLAN.md). The shared shell, title pages, playback, and profile preferences have separate owners.

## Research and decisions

Official sources were rechecked on October 3, 2026 before the resumed implementation. WCAG 2.2 is the published normative accessibility baseline; the linked WAI tutorials and Understanding pages explain techniques and do not define a separate conformance requirement. Explicit native labels, semantic lists, controlled pagination, and the submitted-query interaction are implementation/product choices consistent with that guidance.

Use ordinary links for title/collection navigation and native buttons for commands. Filter controls have visible labels; related controls use a fieldset and legend. Keep the submitting/search action distinct from editing the search field. This follows [WAI form labeling](https://www.w3.org/WAI/tutorials/forms/labels/) and [grouping controls](https://www.w3.org/WAI/tutorials/forms/grouping/).

Loading and result updates use a persistent polite status region without moving focus. Failed requests expose their own retry command; a failed additional page keeps existing cards usable. Empty results and API failures remain separate states. Preserve focus on the Load more command and announce the loaded count. See [WCAG 2.2 Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). These techniques and browser assertions do not establish complete assistive-technology conformance.

Search input editing does not navigate, fetch, or save. Enter or the native submit button publishes the query to the URL; subsequent labeled filters update that submitted result set and retain focus. See [WCAG 2.2 On Input](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html). Keep result counts/waiting/no-result copy in a short status region rather than marking the entire gallery live, so assistive technology does not re-announce every card.

Keep filters, submitted query, sorting, and pagination depth in the URL. Entering a title carries the full originating URL through the shared `titleRoute` helper. Returning/reloading replays the authoritative pages for that URL rather than restoring private media from a global cache. SvelteKit recommends URL state for state that should survive navigation/reload, and warns against shared server state. See [SvelteKit state management](https://svelte.dev/docs/kit/state-management).

Use a small pager factory per route/view instance and pure query-normalization helpers. The controller cancels superseded work, ignores stale completions, deduplicates item IDs, and follows actual cursor responses. A native Load more action is preferable to scroll-triggered fetching for this baseline because users control continuation and retain a stable focus target. Its tradeoff is an explicit extra action. Do not filter a loaded page to simulate server filtering, invent arbitrary numbered pages for keyset APIs, or share profile media in a module singleton.

## Contracts and boundaries

- Catalog/library galleries use the enriched, profile-scoped `listMediaItems` contract, including `library_id`, `type`, `sort`, `order`, `watch`, and `favorite`. See [Tonight browsing contracts](TONIGHT_BROWSING_CONTRACTS.md).
- Search uses the coordinated enriched `/search` contract: `q`, `type`, genre slug, `year`, `rating_min`, `limit`, `cursor`, `sort=relevance|title|year`, `order=asc|desc`, watch status, and boolean favorite. Responses include enriched items, real scoped facets, cursor, and `has_more`. Facets cover the filtered result set across pages; they are never inferred from a loaded client page. The API helper forwards the caller's AbortSignal. The active profile's search policy remains authoritative and returns 403 when disabled.
- Existing `/libraries` and `/collections` management reads require `CanManageLibraries`. They cannot supply ordinary/Kids browsing metadata. Read-only access-scoped library/collection endpoints are a required coordinated prerequisite; management mutations keep their current authorization.
- Collection browsing uses the additive `/browse/collections`, `/browse/collections/{id}`, and `/browse/collections/{id}/items` contracts. Membership pages contain enriched access-filtered items; the default order is membership position. The UI restores that default by omitting `sort`, and supports catalog sort/watch/favorite/type alternatives. Counts and artwork cover IDs are the server's scoped values. Administrative membership remains a separate contract.
- Library listing and selector options use `/browse/libraries`; metadata uses `/browse/libraries/{id}`; media pages use `/media-items?library_id={id}`. The selector follows every accessible-library cursor before offering choices. The list presents only real name/type fields and does not invent unavailable item counts. Management reads and mutations retain their existing guards. A read-only active-profile layout context plus the account capability determines whether the existing scan command and administration link are presented; server authorization remains authoritative.
- Never ship test fixtures, placeholder catalog entries, or private filesystem paths in these views. Reuse the authenticated artwork component and its real fallback behavior.
- Preserve scanning and collection management through their authorized administration destinations; personal browsing does not grant management capabilities.

## Validation

Use pure query/controller tests for URL normalization, cancellation/stale completion, page append/replay, and failures retaining prior content. Real-route Playwright tests use test-only intercepted APIs to check filters/query requests, title return origin, full pagination restoration, independent empty/error states, library scoping, search submission/facets, and collections. They complement the actual server/database access tests.

Run the web check/unit/e2e harness, web build, desktop static build, and relevant contract/profile/accessibility checks documented in [Tonight web verification](../ci/TONIGHT_WEB_TESTS.md). Check the real galleries at 320 CSS pixels, keyboard-only operation, reduced motion, and localized/RTL layouts. Record any unavailable screen-reader/native qualification separately.

## Implementation evidence

The actual `/media`, `/libraries`, `/libraries/[id]`, `/collections`, `/collections/[id]`, and `/search` routes compose focused query, cursor-pager, scoped metadata, filter, and gallery modules. Poster cards use authenticated Artwork and actual watch/availability fields. Library and collection list origins are restricted to their own allowlisted list routes and survive detail/back navigation. Title links preserve the full originating filter/pagination URL through the shared title helper.

The pager belongs to one view, cancels superseded loads, follows server cursors, deduplicates IDs, rejects missing/repeated continuation cursors, and exposes independent initial/append failures. Explicit refresh after a library scan reloads authoritative pages. URL `pages` records loaded depth rather than pretending keyset cursors provide arbitrary page numbers. A failed append keeps its retry target and does not rewrite the URL; successful retry updates the restored depth. Metadata errors have their own retry and cannot appear as an empty gallery.

Search maintains an editable draft independently of its submitted URL query. Real server facets remain available across pages and retain selected filters even when a new result set omits their facet. Native format/genre/year/rating/sort/watch/favorite controls are explicitly labeled outside their selects; labels do not absorb option text into accessible names. No-result, pending, count, and error feedback is separate from the semantic card list. A forbidden active-profile search policy is explained before requesting results.

On October 3, 2026, all 15 T04 real-route Chromium cases passed in the full integrated 42-case run. The seven baseline auth/profile/title smoke cases and all eight viewing-preference cases also passed. The full run's single remaining failure was the Title owner's profile-switch expectation while the shared shell navigated to Home. The integrator restored the safe complete Title URL on routine profile switching, and the unchanged targeted regression then passed. The final submitted-search case also passed after adding the supported ascending-relevance choice. These targeted regressions do not claim a later all-green full-suite run.

The browser cases verify authoritative filter queries, focus retention, submitted search, full-set facets, library-option pagination, catalog and list/detail pagination restoration, safe title/list origins, append failure/retry retaining cards, actual scoped collection membership, standard-profile scan/admin reachability, Kids restricted-title/command visibility, disabled search, metadata retry, empty states, and 320 CSS pixel RTL/reduced-motion reflow. The full Vitest suite passed 115 tests in ten files before subsequent playback-only tests were added; 28 of those directly exercise the new browsing query/pager/facet/metadata behavior. The full Svelte check showed no browsing diagnostics; later playback integration diagnostics remain owned by their modules and do not count as a passing full check.

Library scans ignore completion after the view is disposed, preventing late scan feedback from starting a new page read. Read controllers and artwork clean up their own requests/resources; no private catalog or profile state is kept in a new module singleton. These routes do not constitute native Tauri, zoom, contrast, or screen-reader qualification; browser API interception does not establish server access control or database correctness. Shared web/static-build and actual server verification remain integrator checks.
