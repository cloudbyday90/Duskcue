# Live playback client qualification

## Scope and design

The October 18, 2026 increment joins the [direct fallback](PLAYBACK_DIRECT_FALLBACK.md) live PostgreSQL/FFmpeg fixture to the complete production Player component in installed Chrome and the actual static Tauri application with its bearer transport. The accepted product policy remains web and desktop first, bounded automatic recovery with a visible degradation notice, unchanged source files and one shared server-owned recovery budget. This is implementation of the agreed next increment; it introduces no new playback engine or format policy.

The production Rust `build_router` supplies real domain handlers, authorization, cache controls, request identifiers, compression, CORS, rate limits and security headers. The existing isolated state, PostgreSQL18, packaged FFmpeg, network namespace, owned resource marker and cleanup are retained. No production test-control API is added. The fixture uses private bounded file handshakes for inspecting live output and any deliberately failed owned worker. Its HTTP listener has no published container ports, host mounts or Docker socket.

The host gateway binds only an owned loopback address and forwards to one fixed container-local listener through Docker-exec stdio. Route, method, header, body, response, request-count and deadline bounds apply. Eight data operations include at most two event streams; two separate five-second cancellation slots remain available at saturation. Event streams retain real authentication and bytes with bounded streaming/cancellation rather than fabricated responses. Ephemeral tokens stay out of evidence and URLs. Tauri retains an isolated identifier, user-data directory and keyring namespace; cleanup clears only matching fixture credentials and verifies the owned process tree has exited.

Chrome mounts the actual Player, its runtime, preference loading, menus, telemetry and source service. The application shell and adapter-node deployment proxy are separate boundaries. Tauri runs the full static product shell, restores the fixture's real session through the native keyring and uses its existing HLS requirement for bearer media. A source-default 880 Hz track allows Chrome's actual default-track policy to choose native direct playback; selecting an alternate track must continue forcing HLS. Observation code may measure state, native trusted errors, presented frames and decoded audio, but must not inject decoder errors, recovery responses or capability decisions.

## Research and alternatives

Official sources were discovered through the connected web-search MCP service and checked on October 18, 2026. [Playwright's browser guidance](https://playwright.dev/docs/browsers) explains why branded browsers are necessary when codec availability matters. [Its WebView2 guidance](https://github.com/microsoft/playwright/blob/main/docs/src/webview2.md) describes CDP attachment and a distinct user-data folder for each run. [Tower HTTP's CORS reference](https://docs.rs/tower-http/latest/tower_http/cors/struct.CorsLayer.html) distinguishes allowed origins, headers and credential policy; the harness must preserve the repository's actual production policy rather than supply permissive replacement responses. The current local API relies on SameSite=Strict cookies, JSON request parsing and CORS; it has no separate CSRF-token middleware. This qualification must not imply one exists.

[The Web Audio standard](https://www.w3.org/TR/webaudio/) defines FFT frequency bins, dB values and fresh sample windows. Frame counts plus a fresh selected-frequency measurement are stronger than a manifest download, but do not establish physical audibility or perceptual A/V synchronization. Timestamp probes and source-position checks provide a separate timing bound. [Tauri's HTTP release notes](https://v2.tauri.app/release/http/v2.7.0/) also illustrate why redirect scope is a security boundary; the test bridge rejects redirects and cannot choose an arbitrary upstream. This does not introduce that plugin into Duskcue.

| Option | Benefits | Costs and limits | Decision |
| --- | --- | --- | --- |
| Retain shared-module/API-fixture tests alone | Fast, precise failure diagnosis | Cannot establish actual Player and production API integration | Keep as regression coverage |
| Join the actual clients to the isolated real backend | Exercises UI notices, authorization, lifecycle, real decoding and seeking without touching the user library | More test transport and ownership code; platform-dependent native build | Recommended increment |
| Exercise the user's running server and library | Closest deployment environment | Mutates real viewing history and credentials; poor reproducibility | Use disposable fixture instead |
| Add VLC/libmpv or another playback engine now | Potential additional decoder/container coverage | Another authentication, process, packaging and update lifecycle before a measured need | Defer pending format/device evidence |

## Recommended stack and acceptance

Keep the Rust/Axum authorization and lifecycle owner, managed FFmpeg software SDR fallback, hls.js plus native browser media, Svelte Player and Tauri/WebView2. Use ES Module qualification services and existing typed test suites. No CommonJS, release, branch or production test bypass is required.

Require a genuine native Chrome code-3 event after direct frames, a visible conversion notice, the same logical session, one committed recovery attempt, selected default audio and fresh HLS frames. Seek after promotion through the actual UI, inspect the replacement generation and decode its fragment independently: the admitted High/level-4.0/30-fps H.264 and 48-kHz AAC profile, selected global streams, source offset and spent budget must persist. Each independently probed audio/video stream must start within 250 ms of its replacement timeline and their timestamp difference must be at most 100 ms. This bounds muxed timestamp alignment; it does not establish perceptual synchronization. Require actual desktop bearer media, real backend state, pause/seek/close behavior and owned credential/process cleanup. Authentication and profile refusals must allocate no output. Record actual runtime identities, source/image hashes, all successful and failed gates, and the production no-cache Compose evaluation below.
