## Research and decision

PostgreSQL requires a unique order for reliable bounded pages; large offsets still compute skipped rows. Composite row comparisons support keyset traversal, but nullable sort keys require explicit treatment. See [PostgreSQL LIMIT](https://www.postgresql.org/docs/current/queries-limit.html), [row comparisons](https://www.postgresql.org/docs/current/functions-comparisons.html), and [ORDER BY](https://www.postgresql.org/docs/current/queries-order.html).

Axum's [Query extractor](https://docs.rs/axum/latest/axum/extract/struct.Query.html) handles typed query deserialization; semantic validation belongs in the service. Microsoft's [REST cursor guidance](https://learn.microsoft.com/en-us/azure/data-api-builder/keywords/after-rest) describes continuing an ordered query with a cursor while preserving its filters. [SQLx QueryBuilder](https://docs.rs/sqlx/latest/sqlx/struct.QueryBuilder.html) binds user values separately from SQL; only validated fixed sort expressions are appended as SQL. The shared access CTE uses `NOT MATERIALIZED` so PostgreSQL can push parent/cursor constraints into its scans; [PostgreSQL CTE guidance](https://www.postgresql.org/docs/current/queries-with.html) describes the repeated-computation tradeoff.

Keyset pagination is efficient and avoids shifts caused by insertions before an offset, at the cost of no arbitrary page numbers. It does not provide a snapshot when activity, metadata, or permissions change. The selected design uses a unique UUID tie breaker, fetches limit + 1 accessible records, and binds new opaque base64 JSON cursors to the selected profile, route, parent, and filters. Authorization is re-evaluated for every page; cursors convey no permission. Clients restart from the first page after mutations or profile/filter changes.

## Routes

| Route | Query | Order |
|---|---|---|
| `GET /api/v1/media-items` | Existing `library_id`, `type`, `limit`, `cursor`, `order`; additive `sort=added\|title\|year`, `watch=all\|watched\|unwatched\|in_progress`, `favorite=true\|false`, `genre_id`, `year` | Default `added desc`; added uses UUIDv7, title uses sort title + ID, year uses premiere year + ID with unknown years last |
| `GET /api/v1/media-items/continue-watching` | `limit`, `cursor` | Actual profile activity: `last_played_at DESC, id DESC` |
| `GET /api/v1/media-items/{series_id}/seasons` | `limit`, `cursor` | `season_number ASC, id ASC` |
| `GET /api/v1/media-items/{season_id}/episodes` | `limit`, `cursor` | Known `episode_number ASC, id ASC`; unknown numbers last |

Pages return `{ "items": [...], "cursor": null, "has_more": false }`. Limit defaults to 20 and must be 1–100. Invalid semantic queries, malformed cursors, and cursor reuse for a different profile/route/filter return `VALID_001` (422). Primitive query deserialization failures retain Axum's 400 response. The existing base64 `{id}` catalog cursor remains accepted for the default added sort only. Callers preserve all query parameters on continuation. Empty pages have no cursor.

## Item fields

Every browsing item retains the existing `MediaItemResponse` fields, including stable `id`, `library_id`, `type`, title, dates, ratings, and metadata. Additive fields:

| Field | Meaning |
|---|---|
| `duration_ms` | Positive healthy-file duration preferred, then positive catalog runtime; null if unknown |
| `availability.can_play` | Whether the item has a healthy local media file; false for containers and unavailable items |
| `availability.healthy_file_count` | Healthy files for this media item only; no raw filesystem paths |
| `watch_state` | Selected-profile `is_watched`, `is_favorite`, `resume_position_ms`, `play_count`, nullable `last_played_at`; defaults for absent state |
| `series_id`, `series_title` | Episode/season parent identity; episode title remains the episode's own title |
| `season_id`, `season_number`, `episode_number`, `absolute_episode_number` | Real subtype identity and ordering; unknown episode numbers remain absent |
| `episode_count`, `available_episode_count`, `watched_episode_count` | Seasons only: counts of accessible child episodes, playable children, and profile-watched children |

Watch filters apply to the record's persisted profile watch state; unplayed records are unwatched. `in_progress` means not watched with a positive resume position and a real last-played timestamp. Favorites likewise belong to the selected profile. Catalog title/year sort ties use UUID; year is premiere-date year, and unknown dates are last in either direction.

## Access and lifecycle

The authenticated session selects the owned profile. Requests cannot supply another user or profile ID. Queries exclude deleted libraries and enforce the account library allowlist before pagination. Kids also require their explicit library allowlist and a known rating at or below their configured maximum, matching existing rating aliases and annotation handling. Restricted items must not affect pages, cursors, or season counts. Parent subresources additionally assert access to the requested parent and reject incorrect parent types.

Browsing responses use `Cache-Control: no-store` because their watch state, counts, cursors, and visibility belong to the selected profile. The existing single-item metadata endpoint retains its metadata-only cache contract.

The new browse handlers reject a session still requiring initial profile selection with `409 PROFILE_014` before loading its personal catalog. Shared `media/access.rs` owns this selected-profile boundary and account/Kids library and rating predicates; library, collection, and subsequent search reads reuse those predicates rather than copying a different access rule.

Continue watching spans all permitted movies and episodes with positive resume position, real last-played activity, and `is_watched=false`; completed records are excluded. It includes unavailable entries so the UI can explain why playback cannot start. This does not copy the TV feed's bounded one-minute threshold or infer activity from catalog creation dates.

Episode traversal covers the full selected season by following every cursor. The client must not infer later episodes from a catalog page or wrap to episode one. Unknown numbered episodes are displayed but cannot establish numeric next-episode ordering. Playback authorization remains enforced by the existing playback routes, even after browsing has reported availability.

## Verification

### Read-only library, collection, and search extensions — in progress

The existing `/libraries` and `/collections` reads are administration contracts guarded by `CanManageLibraries`; their response data includes management details. Tonight's ordinary-profile browsing requires additive read-only contracts, preserving every existing management guard and mutation. `GET /api/v1/browse/libraries` and `GET /api/v1/browse/collections` return `{items,cursor,has_more}` with profile-bound cursors. Library rows expose only `{id,name,type}`. Collection rows expose `{id,name,description,item_count,cover_media_item_id}`; counts and cover IDs include only visible, non-missing members. Direct `GET /api/v1/browse/libraries/{id}` and `GET /api/v1/browse/collections/{id}` return the corresponding scoped row or 404. No root paths, builder configuration, hidden collections, or administrator metadata are exposed.

`GET /api/v1/browse/collections/{id}/items` returns `MediaBrowseListResponse` with the same supported type/sort/order/watch/favorite filters and cursor rules. Default collection ordering follows membership position with ID as a tie breaker. Enabled visible/featured collections appear only when their optional library and at least one member are accessible to the active account/profile; an inaccessible or empty filtered collection does not reveal restricted titles/counts. Item access and Kids ratings apply before pagination through the shared media access query.

The existing search endpoint needs additive `cursor`, `has_more`, enriched item data, and actual `sort=relevance|title|year`, `order`, `watch`, and `favorite` filters. Keep `q`, type, genre slug, year, minimum rating, and facet semantics; apply account/profile/Kids filtering before both pagination and facet counts. Bind cursors to the query, filters, sort, and profile, with stable ID ties and deterministic null-year placement. Preserve existing plain-text full-text search rather than treating user input as SQL or a query-language fragment. Search remains disabled when the active profile's existing search policy forbids it. These extensions are prerequisites currently being implemented; their UI must not present unsupported controls or claim complete results from one bounded page.

Search research reviewed October 3, 2026: PostgreSQL documents [plain-text query normalization and ranking](https://www.postgresql.org/docs/current/textsearch-controls.html) and [the `@@` operator and `ts_rank` result](https://www.postgresql.org/docs/18/functions-textsearch.html). Retain the existing English `plainto_tsquery` and `ts_rank` behavior with bound input; this preserves matching semantics and the existing indexed search vector, though it does not add a multilingual analyzer or advanced query syntax. Relevance ties use title then UUID; year sorting puts unknown years last in either direction. A single shared filtered CTE supplies both the paginated projection and facet aggregation, at the cost of evaluating it once per items/facets statement. Facets count the full permitted matching set under the same filters, rather than one loaded page. Projection, filters, cursors, facets, and metrics have focused modules behind the search facade.

For search UI, [WAI Status Messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages) explains that visible waiting/count/no-result messages qualify as status updates when context does not change, while the entire result list does not. Use a concise polite status region for those messages and ordinary semantic gallery links; do not announce the complete gallery on every page append. This is an informative technique supporting WCAG, separate from the product's submitted-search and URL restoration decisions.

Use focused media access, library browsing, collection browsing, and search browsing modules behind the existing domain facades. Shared access SQL has one owner, with no unrelated service-state singleton. All browse responses are no-store. Verify real database pagination, owner/Kids/library boundaries, hidden/disabled/deleted collections, missing members, profile watch/favorite state, cross-context cursors, and metadata omission before marking this extension complete.

Targeted tests cover semantic query validation, malformed and mismatched cursors, tie-break ordering, unknown values, profile-specific watch state, Kids ratings/allowlists, deleted libraries, unauthorized parent requests, mixed Continue media, unavailable items, complete season traversal, and counts that exclude restricted children. Database-backed checks must execute the SQL against representative fixtures. No schema migration is required for these read contracts.

## Title and Episode gallery decisions — T05

Reviewed current official W3C/WAI sources on October 3, 2026: [WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/), [Headings and Labels](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html), [Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html), [On Input](https://www.w3.org/WAI/WCAG22/Understanding/on-input.html), [Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [accessible names](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/), [disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), and [decorative image tutorial](https://www.w3.org/WAI/tutorials/images/decorative/).

WCAG requires keyboard operation, meaningful structure/names, visible unobscured focus, adequate contrast and target sizing, and programmatically identifiable result/error status. The Understanding, APG, and tutorial pages explain techniques and are informative. Native season selects, ordinary episode links, native technical `details/summary`, and a labeled native personal-rating select reduce custom keyboard/focus work; they provide less custom styling than an application grid/menu. The selected gallery uses semantic lists and normal links, retaining native opening/history behavior and a visible current-episode indicator. Season changes update gallery content and URL while retaining focus; they do not start playback or move to another page. These component choices and loading every season page are product decisions, not uniquely mandated WCAG patterns.

The Title route composes focused load/selection/playback helpers, an Episode gallery, watch actions, and secondary file information. Every seasons/episodes cursor is followed; failed traversal is an explicit error with retry, never a falsely complete partial gallery. Only the selected season's full episode list is loaded. A selected episode must belong to that accessible season, and its current watch state is re-read before playback. Missing/revoked metadata, watch-state failures, missing files, and unavailable media retain the title and origin where possible and provide visible error/retry actions. Requests abort on cleanup, and stale completion cannot replace the new title/season/profile.

The URL stores `season`, `episode`, and an allowlisted internal `from` destination. Playback navigation uses `playRoute` with `return_to` set to the full series/movie Title URL, plus a freshly checked healthy file ID. Back is an actual link to the retained origin. Episode selection links preserve origin; unknown or no-longer-permitted selection is explained rather than playing a different episode. Playable controls use real file health and watch data; completed items offer Play from the beginning. Favorites, watched-state changes, personal rating, and explicit per-file playback remain available. Decorative artwork has an empty text alternative beside visible title text; protected artwork and fallbacks use the shared Artwork component.

Verification will cover complete page collection, duplicate/cyclic cursor rejection, invalid selections, healthy-file choice, fresh resume/watch state, full return destination, failures/cancellation, and actual keyboard/browser journeys. Native screen-reader/Tauri qualification is recorded separately when unavailable; automated service/build checks do not establish it.

The resumed T05 review rechecked [WAI form labels](https://www.w3.org/WAI/tutorials/forms/labels/), Focus Order, and Status Messages on October 3, 2026. Explicit `label/for` associations provide stable names for season and rating controls, including two separate rating groups. They are an informative recommended technique; WCAG requires an identifiable label/name and meaningful relationships, not that particular syntax. Retry removes its original control while the affected scope reloads, so completion focuses that scope's heading only when focus otherwise fell back to the document; a user's new focus is preserved. Static headings receive `tabindex=-1`, avoiding extra stops in normal Tab order. Primary playback errors and retry actions remain visible beside disabled playback controls rather than requiring the technical disclosure to be opened. This costs a small amount of duplicate explanatory text in the disclosure while making the failure actionable. These are focused component/route changes; transport, pagination, selection, and playback preparation remain separate stateless services.

Movie watch/file retry refreshes those two scoped reads while retaining usable metadata and artwork. Episode detail retry retains the selected heading and gallery while its watch/files reload; metadata or incomplete-season traversal retry restarts the Title load. All retries stop stale completion after title/profile destruction. Tests distinguish file failure from no healthy files and completed state from positive stale resume positions.
