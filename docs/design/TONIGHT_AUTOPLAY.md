Status: focused services implemented and unit-verified; player integration qualification pending; October 3, 2026. This document owns the resolver and per-player timer service for T07 in the [Tonight implementation plan](../branding/TONIGHT_IMPLEMENTATION_PLAN.md). Player transport, fullscreen, track preferences, and UI integration remain owned by their existing player modules. See [Tonight browsing contracts](TONIGHT_BROWSING_CONTRACTS.md) for real episode identities, complete pagination, and access boundaries.

## Research and decision

Official W3C/WAI sources reviewed October 3, 2026: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html), [Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html), [Media Players](https://www.w3.org/WAI/media/av/player/), [Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [Focus Order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html), and [Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html).

WCAG 2.2 is the normative baseline. The Understanding pages and WAI player guidance are informative explanations and recommendations. Timing Adjustable requires an applicable mechanism to disable, adjust, or extend a content-imposed time limit; this product uses saved autoplay Off before the countdown is encountered. Ten seconds is a product choice, not the criterion's required duration. Cancel during those ten seconds provides additional control and leaves an untimed Play next action, but does not replace the pre-encounter Off mechanism. Focus/popover/visibility pauses protect ongoing interaction; a focus-only pause is not the explicit persistent pause/stop mechanism described by Pause, Stop, Hide.

Native labeled actions and visible focus retain keyboard operability. The player must keep end-of-episode actions and the stable status region inside its fullscreen subtree and prevent idle hiding of focused controls. Announce the next title and state changes with a stable status message; changing visual seconds must not cause speech every second. Focus remains with the user during discovery/countdown. If an explicit action removes its control, the player restores focus to a meaningful surviving control/content; automatic playback must not strand focus in hidden content. Caption/track/quality/speed behavior is preserved by the player owner.

The selected design separates real episode discovery from timing and from transport. A per-instance controller needs explicit lifecycle calls and UI pause signals, adding integration work compared with embedding a timer in the component. In return, its scope, aborts, cancellation, and exactly-once transition can be tested without creating another global player singleton. Prefer that design over unscoped mutable timers or a countdown derived from playback progress.

## Episode resolver

`resolveNextEpisode(item, { signal, readers })` follows every page of the current season through the existing media browsing contract. It accepts only real episode identity with series/season IDs and a known numeric episode number. It locates the current ID in the fresh ordered list and chooses the immediately following real item. Gaps in numbering are valid; IDs and server ordering determine identity. Unknown numeric order, a missing/revoked current ID, malformed/foreign items, and incomplete traversal never create an inferred successor. It does not move movies, cross season boundaries, wrap, or skip an unavailable successor to play a later episode.

The result is `{kind, episode, reason}`. `kind` is `available`, `unavailable`, `none`, or `unordered`; available/unavailable retain the actual next episode DTO. `none` means no successor or no episode context, and `unordered` means numeric ordering cannot authorize automatic advancement. Access/transport failures reject with a recoverable error. Browse availability is advisory: the player's transition callback rechecks the next item's watch/files and playback authorization before starting it. Requests share cancellation and active-profile transport scope; the resolver accepts no user/profile override.

## Per-instance controller contract

`createAutoplayController({ resolveNext, onChange, onPlayNext, clock })` creates one controller per player lifecycle. `clock` optionally supplies monotonic `now`, `setTimeout`, and `clearTimeout` functions for deterministic tests. The duration is ten seconds.

- `ended({item, profileId, autoplayEnabled, preferencesReady})` is called only by the actual media-ended event. Synthetic progress/near-end events do not call it. Repeated ended calls for the same current profile/item do not recreate work or a cancelled timer.
- `setPreference({autoplayEnabled, preferencesReady})` receives the confirmed current-profile preference. Unknown/loading/failed preferences cannot authorize a timer. Off removes a running timer. Explicit On can authorize the initial countdown, but never undo persistent cancellation for that ended item.
- `setPaused({focusWithin, disclosureOpen, documentHidden})` merges the supplied environmental reasons. Any reason pauses the remaining duration; releasing one reason cannot override another. It owns no DOM listeners.
- `cancel()` permanently removes the timer for this ended item and retains available Play next without a time limit. Focus/visibility/preference changes and repeated ended events cannot reopen it.
- `playNext()` attempts an available successor once. It clears timing before invoking `onPlayNext(episode, {signal, mode, profileId, currentItemId})`; `mode` distinguishes manual and automatic transitions. Callback failures become recoverable errors and do not automatically repeat.
- `retry()` resolves again and leaves successful recovery untimed. This re-evaluates access/availability rather than retaining a stale playable decision.
- `reset()` invalidates the current generation, aborts reads/transition work, clears timers, and publishes idle state. Call it on new playback/source, profile/account/server change, and replay of the same item. Environmental pause signals remain independently controlled.
- `dispose()` invalidates/aborts/clears without further UI callbacks. Call it on destruction.
- `getState()` returns a state snapshot. The state includes `phase`, `nextEpisode`, `reason`, `remainingMs`, `seconds`, `paused`, `cancelled`, `error`, and a stable `announcement` code. Phases include idle/loading/countdown/ready/unavailable/none/unordered/error/transitioning/transitioned.

An enabled, ready preference starts timing only after complete next-episode discovery succeeds. Off or unresolved preference produces an untimed ready action. A generation token plus AbortSignal prevents stale resolution/transition completion from publishing into another media/profile. The transition gate closes before invoking the async callback, so duplicate ended events, timer/manual races, and repeated clicks cannot start two transitions. The callback must honor its signal and independently validate its current scope; a service cannot revoke side effects that an integration callback has already ignored cancellation for.

## Verification and integration acceptance

Focused unit tests must exercise complete real ordering and cursor traversal, missing/foreign/unknown identity, last episode and movie behavior, unavailable successor, stale aborts, saved Off/unresolved preferences, the ten-second deadline, all pause reasons and preserved remaining time, persistent cancellation, exactly-once manual/automatic races, retry, reset/disposal, and transition failures. Final browser/player checks must additionally prove actual ended wiring, saved Off before encountering the timer, native keyboard/focus operation, stable live announcements, fullscreen retention, track/speed/quality preservation, real file authorization, and navigation/profile cleanup. Unit tests do not establish assistive-technology or full WCAG conformance.

## Autoplay card presentation contract

The presentation review rechecked Focus Order, Status Messages, and [ARIA22 status technique](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22.html) on October 3, 2026. A persistent polite/atomic status node exposes meaningful state changes without moving focus; the visual countdown is excluded from that live content. This is an informative technique supporting WCAG status requirements. Cancel-to-Play-next focus restoration preserves a meaningful location after an explicit action removes its invoking control; it is a chosen implementation of the focus-order requirement rather than a mandated widget pattern. Ordinary native buttons retain native keyboard operation and do not need application-menu semantics.

`AutoplayCard.svelte` accepts controller `state` and `onplaynext`, `oncancel`, `onretry`, and `onfocuschange(boolean)` callbacks. Always mount it inside the player's fullscreen subtree. It keeps the polite status node mounted even when its visible card is hidden for idle/none/transitioned state; movies therefore have no next-episode card. Loading, countdown, untimed ready, recoverable error/unavailability, and unknown-order explanation use real controller state and real next-title text. Countdown offers Play now and Cancel. Saved Off/cancellation offers persistent Play next. Error/unavailability offers Retry, which the controller already makes untimed on success; the component cannot create or resume timers itself. Unknown numeric order is explained without a false playback action.

Focus within the card reports a pause signal; moving between its buttons does not release that signal. Leaving, hiding the section, and destruction release it. A post-render check on phase changes also clears a stale signal if removal of a focused control did not emit focusout. Explicit Cancel records whether its button held focus and, after the parent synchronously publishes cancelled state, restores focus to Play next only when focus otherwise fell back to the document. Explicit Retry also recovers focus after its callback completes, preferring Play next, then another Retry, then the surviving heading; the callback should return its retry promise. Other state transitions do not steal focus. The component owns no global listener, transport, preference, timer, or controller instance. The root positions its flow-layout wrapper above transport/captions. Native targets are at least 44px, text wraps at 320 CSS pixels/RTL, and there is no animation to require a reduced-motion exception. Browser verification of focus and speech remains required in the integrated player.

## Focused implementation evidence

The resolver is implemented in `clients/web/src/lib/playback/next-episode.js`; it reuses the existing complete page collector and the episode browsing API without another mutable transport store. `clients/web/src/lib/playback/autoplay.js` owns one instance's context, generation, abort controller, environmental pause reasons, deadline, and transition gate. Timer callbacks are generation-bound as well as cleared, so an already queued callback cannot change a later source/profile. There are no DOM listeners, player transports, track selectors, preference storage, or global mutable player state in these modules. The UI owns those responsibilities and calls the documented lifecycle methods.

On October 3, 2026, `node node_modules/vitest/vitest.mjs run tests/unit/next-episode.test.ts tests/unit/autoplay.test.ts` passed all 43 tests across two files. Meaningful coverage includes a successor beyond a hundred-episode first page, all current-season pages before making a decision, numbering gaps/duplicate known numbers using real server identity order, missing/reordered/foreign/unknown identities, unavailable next without skipping, incomplete reads, cancellation, saved Off and unresolved preferences, precise ten-second advancement, each environmental pause with subsecond remaining time, overlapping reasons, persistent Cancel, untimed recovery, callback failure, old-scope reads/queued ticks/transition completion, per-instance isolation, reset/disposal, and manual/timer/repeated-click races. Announcement codes remain stable while visual seconds change.

Both service files passed `node --check`; scoped whitespace checks passed. The coordinated Svelte check reported no diagnostics in either service module. Its owned test-mock argument inference diagnostics were corrected with explicit callback parameters, and all 43 tests passed again. A later coordinated full check and actual player/browser integration remain separate evidence. No final build or new browser server was started for this service scope.

The focused AutoplayCard presentation compiles with Svelte's client compiler with zero warnings. Eighteen uniquely named English message keys were added; its Paraglide generation and final type/browser interaction checks run in the coordinated player integration scope. The component itself adds no dependency or harness/configuration change, and its local cleanup guards prevent late focus recovery after destruction. This compiler check does not prove screen-reader announcement behavior or keyboard focus restoration in a browser.
