## Inspected baseline client facts

- Tauri builds the shared web client; a second catalog implementation is unnecessary. Before this increment there was no Live TV route, navigation entry or client catalog adapter.
- The shell owns selected-profile readiness, exposes its active-profile context, cancels profile-scoped requests and remounts scoped children after local/cross-tab profile changes. Profile switches currently return to Home except for the existing media-detail preservation rule. Preserve that behavior.
- `lib/api/core.js` already uses web cookies or selected-server bearer authentication and checks profile scope after response-body parsing. Reuse it without exposing credentials to catalog components.
- Cached account capabilities and profile-list records cannot establish current Live TV entitlement. The profile response has no Live TV access field, and session revalidation does not reload current capabilities. Every catalog response remains authoritative.
- The existing `createCursorPager` ignores catalog context, keeps prior pages after append errors and exposes unbounded `loadAll()`. It cannot directly provide strict snapshot/profile fencing, bounded screen retention or explicit restart behavior.
- Before this increment both the JavaScript desktop allowlist and native incoming-route parser omitted `/live-tv`. Adding a client destination requires deliberate route integration and tests, rather than accepting arbitrary paths.
- Existing gallery components provide polite status, distinct empty/error states, focusable busy controls and semantic CSS tokens. Reuse these patterns through small catalog-specific components.
- English messages belong in `messages/en.json`. Regenerate the checked-in message-availability map and retain `messageLocale` for actual English fallback language. Seven preview locales remain review-gated; this increment must not activate them.
- Before this increment there was no general raw-language-label helper or programme time-range/uncertain-time presenter. The audio/subtitle language helper accepts a narrower code set and is not a general XMLTV language validator.

## Confirmed client contract

- A source-neutral `/live-tv` destination in the existing shell. Discoverability for selected standard profiles is confirmed independently of stale cached capabilities; current GET results authorize content. Kids has no navigation entry or content surface.
- Initial channel pages do not silently select a channel. Explicit channel selection loads its guide. A chosen six-hour window survives channel selection within the current view; Return to current time captures a new instant. No polling or automatic window movement.
- Scheduled and incomplete-time views use the two existing per-channel APIs. Missing/undeclared/ambiguous guide evidence, overlap/conflict/clump flags, raw rating labels and raw times remain distinguishable. No now/next computation, inferred end, rating classification, playback action or source-management mutation.
- Retention is one current channel page and one current programme page, twenty entries each, plus at most sixty-four cursor-history entries per lane. Previous/Next/First replace visible pages. There is no load-all, infinite append or persisted cursor/metadata/selection state.
- Each page must match selected profile, opaque decimal-string profile revision and current snapshot. Programme channel/view/window must also match the request. The client does not invent or increment the database revision. Obsolete responses cannot publish after cancellation, channel/view/window changes, profile/server/auth changes or disposal.
- Use a focused bounded-JSON option inside the shared request lifetime: one MiB for success/error bodies, explicit no-store and fixed safe catalog errors. Do not use raw-response escape paths that end shared scope ownership before parsing. Existing callers retain their behavior when the option is absent.
- Use a ten-second client operation deadline, at most one channel and one guide operation concurrently, bounded decoded shapes and no automatic retries. Server work/release/admission limits remain unchanged.
- Any catalog request failure clears rendered catalog data. A 409 requires explicit Reload; 429/503 respect valid Retry-After before manual retry. A 401 uses current-context session revalidation without expiring a newer session or converting a network error into logout. Fixed localized messages omit raw error details, cursors and imported text.
- Keep screen state in memory only. Dispose on route exit/profile/server changes and clear on page-history restoration. Do not use local/session storage, IndexedDB, page URL queries, route snapshots or service-worker storage for catalog data.
- Prefer interface-language text, then untagged or first supplied text, retaining every bounded variant in disclosures. Display imported text as text, not HTML or links. Keep raw language labels separate from a conservative well-formed locale subset used for attributes; unknown language does not inherit a false UI-language claim.
- Show localized programme instants with dates and a device-zone label. Raw/reduced-precision/missing times stay explicit. Formatting limitations must not invent a timestamp. Preserve exact server time strings for context comparison/details rather than reducing protocol precision to JavaScript milliseconds.
- Use persistent polite status, visible loading/empty/error states, native focus behavior and semantic headings. Channel selection can move focus to the guide heading; page controls retain focus; clearing removed content must restore a stable logical target without stealing focus from navigation outside the view. Responsive layout, disclosures and metadata must work at 320 CSS pixels, zoom and RTL.

The user confirmed the complete scope after `896ced0`, including source choice, discoverability, failure clearing, bounded memory-only state, deadlines and actual browser/native qualification. Proceed under that authorization without reopening settled choices.

## Implementation ownership

The shared `/live-tv` route composes small channel, guide, programme, text-evidence and pager components. The shell exposes the entry for standard profiles; both desktop route boundaries explicitly recognize it. `lib/api/live-tv.js` uses the existing cookie/bearer transport with no-store and a one-MiB JSON budget. `lib/api/json-body.js` owns byte-counted UTF-8 decoding; `retry-after.js` owns delta/HTTP-date interpretation inside the original request scope; unrelated callers retain their existing behavior.

`lib/live-tv/controller.js` owns screen lifetime, independent channel/guide cancellation, ten-second deadlines, replacement paging and explicit recovery. It rejects overlapping page actions while allowing deliberate channel/view/window changes to cancel obsolete guide work. `decode.js` projects an allowlist, checks fixed shapes and UUIDv7 snapshot-entry IDs, preserves decimal revision strings and rejects mismatched profile/snapshot/channel/view/window evidence. `paging.js` bounds each cursor history to sixty-four entries; no metadata is stored in that history. `instant.js` compares protocol instants at microsecond precision and uses milliseconds only for presentation/window arithmetic. `presentation.js` owns conservative language handling, preference and device-time formatting; unavailable time-zone formatting remains explicit.

The current screen retains at most twenty channel and twenty programme records. Imported text is escaped, direction-isolated and never used as HTML, artwork, navigation or a playback source. Failed requests discard both lanes. Reload begins at First with no selected channel; failure and recovery restore logical focus only when the removed control owned focus. A focused document-language service synchronizes HTML language/direction with the resolved runtime locale, including the static Tauri fallback document; it changes no locale availability or server preference. Existing current-context session revalidation handles 401 without automatic catalog replay. Page exit, profile/server remount and history restoration discard the view.
