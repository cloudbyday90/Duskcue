# Tonight Desktop Server Selection

Created October 3, 2026. This focused implementation completes the selected-server entry UI for the shared SvelteKit/Tauri frontend. Native connection and credential persistence remain in `clients/web/src/lib/desktop/session.js` and existing `clients/desktop/src-tauri/src/lib.rs` commands. The root layout owns session/bootstrap invalidation and shell integration.

## Research and recommendation

Official guidance reviewed October 3, 2026: [WAI explicit labels](https://www.w3.org/WAI/tutorials/forms/labels/), [form notifications](https://www.w3.org/WAI/tutorials/forms/notifications/), [WCAG 2.2 status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html), [WAI modal dialog focus](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [native HTML dialog technique](https://www.w3.org/WAI/WCAG22/Techniques/html/H102), and [Tauri frontend commands](https://v2.tauri.app/develop/calling-rust/). Native labeled controls reduce custom keyboard/focus machinery; a native dialog provides modal focus containment and Escape, with explicit opener restoration. Separate test/save commands would expose finer progress but duplicate the existing combined session service and risk stale success when input changes. Recommend one explicit **Test and connect** action with truthful combined pending status, retained input on failure, and retry using the same action.

The URL input uses text with `inputmode=url` because the existing native normalizer accepts a bare host and supplies its scheme and public port. Browser `type=url` validation would reject that supported input. URL normalization and local/private/exposed policy stay native; expose only existing `local`, `remote_vpn`, and `exposed` values, with HTTPS required by native exposed mode. No account, token, invented server-name field, saved-server list, or health body is created by the selector.

## Integration contract

`initializeDesktopSession()` and `selectDesktopServer({input, networkMode})` return `{isDesktop, server, requiresServerSelection, hasToken}`. `server` is the native `{origin, network_mode, display_name?, last_connected_at?}` snapshot; token contents never enter the UI callback. Selection performs normalize → health/ready test → native connection save → origin-keyed credential restoration → API core origin/token configuration. Native errors and unhealthy results reject, and drafts survive rejection.

`DesktopServerSelector.svelte` accepts `server`, `onbeforeselect`, `onselected`, and `onsettled`. The shell renders it after desktop initialization reports `requiresServerSelection`, before issuing authenticated API/profile requests. `onbeforeselect` requests the shared unsaved transition, stops playback, aborts old scope work, disconnects events, and gates new work while keeping the current selector rendered. Clearing keyed account/profile children at this point would destroy the form before its native command begins. `onselected(snapshot)` scrubs old account/profile rendering and bootstraps the accepted server. `onsettled(snapshot|null)` runs in `finally`; rejection/cancellation lets the shell restore the prior scope without losing the server draft. The selector excludes its own submitted server draft from that preselection guard while preserving guards owned by viewing preferences; it registers its draft for ordinary navigation/profile exits and blocks route transitions during preselection/native work.

The `/settings/server` route consumes `setContext('desktop-server-selection', {beforeSelect, selected, settled})` supplied by the shell, so switching uses the same lifecycle. It does not own shell auth state. Settings links to it only in Tauri; in an ordinary browser the route explains that the connected website supplies its server. Existing desktop route allowlists already accept this path. Native first-run/credential/packaging qualification remains separate from browser interception.
