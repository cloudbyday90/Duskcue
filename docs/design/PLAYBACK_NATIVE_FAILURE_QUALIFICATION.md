# Native worker-failure qualification

## Scope and confirmed direction

The October 18, 2026 follow-up to [live-client qualification](PLAYBACK_LIVE_CLIENT_QUALIFICATION.md) implements its recommended deterministic native worker-failure gate. Keep the actual static Tauri application, production router, native keyring/bearer transport, managed FFmpeg sandbox and real watchdog/heartbeat lifecycle. Preserve original files, selected streams, profile, logical session, pause intent and the shared recovery budget. This increment qualifies the agreed web/desktop recovery behavior; it adds no playback engine or format policy.

The short ordinary HLS source can finish before presentation. Add a separate bounded 60-second regular-file native candidate and a default-off `playback-qualification` Cargo feature. One immutable manager-local `OwnedPacedInput` admits only its canonical regular non-symlink file beneath the fixture root and retains metadata plus SHA-256 content identity. Read the opened file with a fixed streaming buffer and sixteen-MiB input ceiling, checking descriptor/path metadata before and after hashing. Its fixed input arguments are `-readrate 1 -readrate_initial_burst 2 -readrate_catchup 1`, placed before `-i`; another manager/source retains ordinary arguments, and changed configured identity refuses launch. There is no global registry, mutable policy map, request DTO, database setting, environment pacing option or alternate executable. Production builds retain their ordinary feature selection. The qualification-only hash adds bounded file I/O on each selection and restart.

## Official research and alternatives

Official sources were discovered through the connected web-search MCP service and checked October 18, 2026. [FFmpeg's manual](https://www.ffmpeg.org/ffmpeg.html) documents input read-rate limiting, real-time file simulation and burst/catch-up options. Its [8.1 demux implementation](https://www.ffmpeg.org/doxygen/8.1/ffmpeg__demux_8c_source.html) makes the defaults explicit; fixed values avoid hidden catch-up assumptions. Input seeking can preserve preroll during stream copy, so use known keyframes for this recovery gate and keep arbitrary-playhead fidelity separate.

[Cargo's feature reference](https://doc.rust-lang.org/cargo/reference/features.html) describes explicit feature selection and unification. [Cargo testing](https://doc.rust-lang.org/cargo/commands/cargo-test.html) and [conditional compilation](https://doc.rust-lang.org/reference/conditional-compilation.html) explain why an integration test's library dependency cannot use existing private library-unit-test hooks through `cfg(test)` alone. Qualify both ordinary and opted-in builds, verify the selected Cargo artifact's features and bind the image label/source hash to the mode.

[Linux pidfd signaling](https://man7.org/linux/man-pages/man2/pidfd_send_signal.2.html) provides stable process identity across PID reuse. Reuse the fixture's existing exact parent/start-time/executable/source/manifest checks and pidfd suspend guard. A kill classified as unknown, a fabricated client hint or a fake manager failure cannot establish genuine stalled-worker recovery.

The actual unchanged-metadata failure below motivates checking file contents as well as timestamps. The existing [ring streaming digest API](https://docs.rs/ring/latest/ring/digest/struct.Context.html), discovered and checked during the follow-up, supports fixed-buffer SHA-256 without another dependency or a whole-file allocation. This is fixture-source identity, not a general promise to eliminate filesystem races in unrelated upload paths.

| Option | Benefits | Costs and limits | Decision |
| --- | --- | --- | --- |
| Longer source alone | No server hook | Copy/remux can still complete before the failure point | Insufficient |
| Manager-local, compile-time qualification pacing | Deterministic lifetime through real seek/recovery and sandbox paths; fixed owned-file scope | Separate build configuration and deliberate real-time latency | Recommended |
| Runtime pacing flag or arbitrary FFmpeg wrapper | Easy injection | Expands runtime authority and can bypass managed executable/sandbox guarantees | Reject |
| Synthetic API failure or decoder event | Fast UI regression | Does not establish actual watchdog/heartbeat recovery | Retain existing separate UI tests |

The recommended stack remains the modular Rust playback services, pinned managed FFmpeg, authenticated HLS, shared Svelte/TypeScript client and Tauri/WebView2 desktop application. New qualification orchestration uses `.mjs` ES modules; Rust remains appropriate for server process supervision and native boundaries. Reusing this stack preserves the existing authorization, sandbox and update paths. Its cost is runtime-specific codec qualification and conservative refusal of unsupported HDR processing; adding another native playback engine to pursue VLC/Kodi parity would introduce another authentication, process and update boundary before measured failures justify it.

Paused recovery does not establish arbitrary-playhead copy/remux fidelity, physical audibility, perceptual synchronization or broad format support.

Retain the paced manager outside timed futures so normal, failed and timed-out cleanup all await its actual workers before deleting the fixture root. Keep the pidfd resume guard alive until physical retirement is confirmed. Private control files remain inaccessible as production endpoints; no host mounts, published fixture ports, socket mounts or privilege expansion are required. Existing Windows/Linux admission, sample freshness, compiler deadline and isolation policies remain unchanged.

The new paced mode alone starts its disposable PostgreSQL with `shared_buffers=16MB` and `max_connections=16`, then verifies both actual settings through a local-socket SQL query. Its shared pool permits eight connections, plus one short-lived extra connection pool, and Chrome/native are sequential. [PostgreSQL resource guidance](https://www.postgresql.org/docs/current/runtime-config-resource.html) documents the usual 128-MB cache default; [startup settings](https://www.postgresql.org/docs/18/config-setting.html) support fixed process-local arguments and inspection. This reduces the fixture's internal allocation while preserving its four-GiB ceiling, all admission/reserve thresholds and real transaction behavior. Smaller cache capacity can affect timing and temporary I/O, so the unchanged deadlines remain mandatory. Production and existing qualification modes retain their configuration; actual memory savings require measurement.
