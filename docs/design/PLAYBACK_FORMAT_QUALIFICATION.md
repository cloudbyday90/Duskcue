# HEVC/AV1 reference format qualification

## Scope

The October 18, 2026 increment extends [native worker-failure qualification](PLAYBACK_NATIVE_FAILURE_QUALIFICATION.md) with the six accepted [reference masters](PLAYBACK_RECOVERY.md#direct-play-follow-up-and-format-qualification): HEVC Main 8-bit SDR, HEVC Main10 10-bit SDR, AV1 Main 8-bit SDR, AV1 Main 10-bit SDR, HEVC Main10 BT.2020/PQ HDR10 and HEVC Main10 BT.2020/HLG. Their MP4/MKV variants and the two AV1 WebM variants yield fourteen cases. Ten-bit SDR remains distinct from HDR.

The actual shared Svelte Player runs every case in installed Chrome with cookie transport and in the same isolated Tauri/WebView2 application lifetime with bearer transport. The existing real watchdog recovery gate remains mandatory. No device-profile override, synthetic playback API, manual source replacement or new playback engine is introduced. The current product sends a null device profile, so SDR cases exercise its conservative H.264/AAC fallback. This does not establish automatic source-codec passthrough detection.

## Official research, 18 October 2026

URLs were discovered and opened through the connected search MCP. [ITU-R BT.2100-3](https://www.itu.int/rec/R-REC-BT.2100-3-202502-I/en), approved February 2025, defines PQ/HLG transfer functions and numeric representation. Author PQ neutral patches by inverse EOTF from absolute luminance and HLG neutral patches by the scene-linear OETF, then quantize to ten-bit narrow range. These downscaled diagnostic images do not establish chromatic gamut fidelity or reference viewing conditions.

[FFmpeg framehash](https://ffmpeg.org/ffmpeg-formats.html#framehash) permits decoded-frame comparison. Explicit pixel precision matters: an eight-bit conversion can hide ten-bit damage. Compare the encoded master's decoded pixels against its remuxes, plus frame count, rational timing, selected audio and color/range/HDR metadata. Container time-base differences need rational normalization rather than string equality.

[Media Capabilities](https://www.w3.org/TR/media-capabilities/) reports supported, smooth and power-efficient predictions for an exact configuration and delivery type. Preserve these independently of observed playback and of the production routing decision. [AV1 ISOBMFF binding](https://aomediacodec.github.io/av1-isobmff/) and [HEVC registration](https://www.w3.org/TR/webcodecs-hevc-codec-registration/) require configuration consistent with the bitstream/container. Do not guess generic codec strings or union codec-specific ten-bit results into the server's global bit-depth field.

The official [x265 level-selection source](https://github.com/videolan/x265/blob/master/source/encoder/level.cpp) sets level 8.5 in lossless mode. Use fixed QP1 HEVC Main/Main10 with a maximum absolute flat-patch error of two native code values, fixed before execution. Lossless AV1 requires zero authored-pixel error. Remux comparisons remain exact against each encoded master's decoded pixels. [FFmpeg codec documentation](https://www.ffmpeg.org/ffmpeg-codecs.html) describes the encoder options; actual profile/level and numeric checks determine acceptance. Do not widen tolerance after observing results.

[FFmpeg's setparams filter](https://ffmpeg.org/ffmpeg-filters.html) sets frame color properties without changing sample values. Authored raw references require these properties on the frames as well as output declarations; the qualifier rejects missing primaries or transfer metadata rather than accepting the tags requested on the command line.

[FFmpeg's Opus encoder](https://ffmpeg.org/doxygen/8.1/libopusenc_8c_source.html) exposes initial and final padding; the [Opus encoder source](https://github.com/xiph/opus/blob/main/src/opus_encoder.c) uses 120 samples of lookahead at 48 kHz in restricted low-delay mode. Author the companion tones with 2.5-ms low-delay packets to align that lookahead with the packet boundary. Assert the observed 120-sample pre-skip, zero final discard and exactly 384,000 decoded samples, retaining identical full PCM hashes through MP4/MKV/WebM. This is a fixture authoring choice; it does not trim decoded proof or qualify general Opus end-padding conversion.

[RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) supports stable public problem identifiers and explanatory details. Keep HDR refusal static and typed, without source paths, arguments or internal process errors. This scoped change retains the existing API's `application/json` error envelope; a platform-wide problem-media-type migration is separate.

## Recommendations and tradeoffs

| Choice | Advantages | Costs and limits | Recommendation |
| --- | --- | --- | --- |
| Rust/Axum and managed FFmpeg | Existing authorization, probing, worker ownership and budgets | Representative fixtures are necessary | Retain |
| Six small authored masters | Separates codec, bit depth, SDR, PQ and HLG | Does not cover all encoders or resolutions | Implement |
| QP1 HEVC and lossless AV1 reference checks | Checks numeric signal values and remux precision independently | HEVC uses the fixed tolerance above; not performance evidence | Implement |
| MP4/MKV and AV1 WebM copies | Exercises container distinctions without re-encoding | WebM cannot preserve AAC | Use two Opus tracks: default 880 Hz at global index 2, alternate 440 Hz at index 1 |
| Actual Chrome and Tauri Player | Tests UI, authenticated transport, presentation and seeking | Platform-specific; audio analyser is decoded-signal evidence | Extend existing harness |
| Additional playback engine | Could address a measured gap | More packaging, attack surface and divergent behavior | Defer until measured need |
| Unverified HDR-to-SDR conversion | Broader apparent admission | Incorrect transfer/gamut/range risk | Refuse until reference verified |

The stack remains modular Rust services, pinned managed FFmpeg, shared Svelte/ES-module Player, hls.js/browser media and Tauri/WebView2. JavaScript tooling uses `.mjs`; typed client code may use TypeScript. Rust owns server/native process boundaries. No CommonJS, new branch or release is introduced.

## Corpus and resource boundaries

Generate six 320×180, 24-fps, eight-second video masters sequentially, with motion, binary frame identifiers, precision-sensitive ramps and numeric reference patches. Retain fourteen sources under eight MiB each, per-file SHA-256, actual probe/configuration and tool identity. Remove transient raw frames. Codec execution uses one thread and bounded output/deadlines; copy operations preserve video and the same two audio tracks.

Ingest only an owned source directory through the real scanner, keeping transcode output outside it. Preserve existing H.264-specific assertions and the exact-source native pacing feature. New matrix deadlines apply only to the new mode: 900-second live handshake, 1,000-second direct contract and 1,050-second combined runtime. Memory/CPU/PID ceilings, two Cargo jobs, Linux admission/reserve/freshness checks and default-off qualification pacing remain unchanged. No production test routes, host mounts, published container ports or Docker socket are added.

Serial case starts respect the unchanged production global bucket of 100 requests/minute with a 50-request burst. Each client matrix first waits 30 seconds with no case open; subsequent starts are at least 20 seconds apart in Chrome and 28 seconds in Tauri, whose document initialization and deliberate resume reset add requests. Abortable bounded waits retain monotonic timing and observed request counts in the detailed artifact. Any observed HTTP 429 still fails, retaining a bounded numeric `Retry-After` value. There is no limiter reset, request rerouting or automatic retry. The combined minimum pacing is 684 seconds, within the existing 900-second handshake with room for controls and verification.
