## Research and boundaries

Official sources reviewed October 3, 2026: [WAI Media Players](https://www.w3.org/WAI/media/av/player/), [WCAG 2.2 Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html), [Timing Adjustable](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html), [Playwright routing](https://playwright.dev/docs/api/class-route), and [Playwright Clock](https://playwright.dev/docs/api/class-clock). WCAG is the normative accessibility baseline; WAI Understanding/media tutorials and Playwright guidance explain implementation/testing techniques rather than establishing conformance.

Rechecked October 7, 2026: [WCAG overview](https://www.w3.org/WAI/standards-guidelines/wcag/) continues to identify WCAG 2.2 as the published recommendation; [WCAG 3 introduction](https://www.w3.org/WAI/standards-guidelines/wcag/wcag3-intro/) describes developing draft work. The media-player, timing, and [APG disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) guidance remains applicable. Disclosure tests exercise native Enter/Space/Tab, expanded state, selected choices, dismissal, and trigger focus. Countdown tests separately prove that saved Off removes timing before encounter, that Cancel remains untimed, and that focus/disclosures pause the accepted product countdown. A stable polite announcement between ticks is verified through DOM behavior; spoken assistive-technology output remains separate qualification.

Verify ordinary labeled native commands and actual focus, fullscreen, Escape, and close behavior. Check that focused controls remain available through idle time and that disclosure cancellation/restoration preserves focus. Ten-second next-episode timing needs saved Off before it starts, persistent Cancel, and an untimed Play next action; the ten-second value is an accepted product choice, not a claim that ten seconds alone satisfies adjustable timing.

A real decoded `<video>` must advance its current time, expose positive intrinsic dimensions/duration, and naturally raise its own `ended` event before a test claims playback or an ended transition. A script-dispatched event or mocked media element only proves event/control wiring. Seeking a real clip near its end is allowed for a focused native-ended check, but is recorded separately from continuous playback. JS clock advancement may verify heartbeat/idle/countdown scheduling; it does not simulate real decoding or count as a native media clock.

Browser interception exercises the actual client route and mature playback stack against controlled API responses. It does not prove Rust playback authorization, real server transcoding, hardware decoding, native Tauri, contrast/zoom, or assistive-technology qualification. Keep those limitations explicit; never ship sample media, sample accounts, or fallback UI data in application source.
