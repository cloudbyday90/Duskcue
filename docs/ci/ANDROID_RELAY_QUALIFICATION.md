## Source-supported gaps

Read-only review distinguishes source defects and missing evidence from demonstrated exploits. No credential escape or application memory leak has been established.

| Boundary | Current evidence / required correction |
| --- | --- |
| Accepted/closing sockets | `relay/service.dart` discards the `RawSocket.close()` Future for refused/stale sockets. They are absent from the drain set. Accepting a ninth then retaining its asynchronous close cannot simultaneously satisfy an eight-socket total. Admission policy needs the explicit decision below. |
| Upstream cleanup | `relay/upstream.dart` removes a client after void `HttpClient.close(force:true)`. Neither that call nor `Socket.done` proves native TCP destruction in the locked SDK. Retain connection creation, cancellation, late completion and actual raw close before releasing the upstream slot. |
| Local cancellation | Local EOF closes the local connection but is not wired directly to pending upstream connect/header work. Cancellation must reach that work immediately while retaining its eventual outcome. |
| Writes and scope | A final positive Windows `RawSocket.write()` can represent initiated overlapped I/O. Observe final write readiness/completion before closing; recheck current scope/lease/output between partial writes and after waits. The current three-byte fixture does not establish this behavior. |
| Initialization tag grammar | The unanchored `URI="..."` match in `playlist.dart` accepts `XURI` and publishes a reference despite the required `URI` attribute being absent. Parse the supported tag's exact attribute names and reject duplicates/unsupported grammar before publication. |

| Reference publication | A late variant response can potentially restore references after a newer root removes the variant. Qualify current root reachability/publication revision at adoption, with bounded atomic reference replacement. Immutable VOD output does not justify skipping the race test. |
| Actual format evidence | Existing authored media is 320×180 with mono sine inputs. Requested 480/720/1080 quality and a two-channel ceiling do not prove actual resolution or stereo output. Probe generated output and verify real native presentation. |

The locked SDK adds important details that public API signatures alone do not establish:

- `socket_patch.dart:2200–2262` creates a synchronous raw-server controller and checks pause after each accept callback. Pausing inside the eighth callback stops the next native accept; it does not buffer a batch of already accepted raw objects. Queued OS connections remain backlog connections.
- `socket_patch.dart:1448–1458` describes Windows overlapped writes; its higher-level stream consumer observes write availability before flush completion. `io/socket.dart:795–802` exposes native TCP destruction through the raw close Future.
- `http_impl.dart:2900–2908` closes clients logically without a returned drain Future. `Socket.done` follows the sink, and the high-level socket close path discards the raw close Future. Neither substitutes for retaining the raw transport owner.
- There is no public raw-to-`Socket` constructor. A public-interface adapter over `RawSocket`/`RawSecureSocket`, supplied through `ConnectionTask.fromSocket`, is feasible but becomes an additional stream/sink implementation requiring adversarial qualification. Do not use private SDK constructors, handle-transfer tricks, a fork or global I/O overrides as an ownership bridge.
- `io/secure_socket.dart:774–797,1062–1084` completes secure close from TCP destruction while an active private TLS filter may be destroyed afterward. No public separate filter-drain operation is available. Awaited handshakes, owned API operations and confirmed raw TCP closure must not be described as proof that every SDK-internal native TLS worker has terminated. The completion decision below must be resolved explicitly.

## Confirmed design decisions

1. **Eight-socket admission — confirmed:** pause native acceptance while eight accepted/closing sockets are owned, resuming only after confirmed release. This keeps all eight serving slots and the existing total, but changes excess connection behavior from always-immediate refusal to finite OS-backlog waiting. The operator rejected silently reserving a slot or adding an extra rejection-close allowance. Never forget an accepted close Future.
2. **Outbound transport architecture — confirmed:** keep the SDK HTTP parser with an owned, bounded public-interface raw-socket adapter. This avoids a new HTTP response parser and retains standard framing behavior, at the cost of qualifying another stream/sink owner. Do not substitute a new response parser or private SDK constructor as an unreviewed implementation shortcut.
3. **HTTPS completion guarantee — confirmed:** require every owned public connect/handshake/HTTP operation to settle and await close for every returned underlying raw TCP handle. Explicitly exclude a join of private SDK TLS housekeeping from that claim, retain normal certificate/hostname checks and measure the process under unchanged guards. This is a public-operation/transport completion guarantee, not proof of every internal native worker's termination or an exact RSS ceiling. Never replace HTTPS with plaintext, accept a bad certificate or imply an unobservable join.

The operator explicitly confirmed all three choices. The [design-review skill](../../.agents/skills/grilling/SKILL.md) still requires shared understanding of the complete implementation scope before dependent implementation. Existing approved grant, journal, scope, command/replay, lease and recovery rules are not reopened.

## Proposed qualification structure

Keep composable owners for acceptance, raw connection/stream adaptation, partial/final writing, upstream request lifetime, response validation, playlist parsing/publication and evidence. Avoid a process-wide singleton. Owner close becomes sticky and idempotent: stop admission, request cancellation, join actual owned operations/transport completion, and retain/quarantine failures rather than deriving release from counters or timeouts.

Preserve the agreed eight accepted/closing sockets, four upstream obligations, eight-KiB headers, two-KiB targets, one-MiB playlists, sixteen renditions, 8,192 current references, sixteen-MiB streamed bodies, two 64-KiB application chunks per response, five-second header/connect observations, ten-second idle, sixty-second body and seventy-five-second whole-request ceilings. Resolve timer start points against those definitions without increasing any ceiling. Keep one current and at most one retiring native/relay generation. No queue of playback starts or transport obligations is added.

Use current exact origin/session/profile/context/credential/output and lease checks before admission and byte adoption. Force direct connections; refuse factory origin/proxy substitution, redirect fallback, dynamic target paths and credential reuse from a newer session. For HTTPS, complete verified TLS before exposing a writable HTTP socket to the SDK parser. Admit one owned request before asking the HTTP client for work; neither the client's connection limit nor its internal pending queue is the resource ledger.

The existing request/URI and media-only policy stays narrow. Validate the full supported playlist before any reference publication or byte exposure; malformed refreshes do not partially authorize references. Reject obsolete root membership at late variant publication. Missing/mismatched binary MIME, coding/status/range or body framing fails safely without advertising arbitrary upstream headers. Keep ordinary server 200 responses to legal Range requests valid; qualify 206 with controlled exact-response fixtures rather than changing the backend delivery contract.

## Recommendations and tradeoffs

| Approach | Benefit | Cost / recommendation |
| --- | --- | --- |
| Add more tests around the current implementation unchanged | Smallest source change | Does not fix discarded close completion or final-write behavior; insufficient for the stated ownership contract. |
| Owned raw I/O adapter with SDK HTTP framing | Retains mature framing/TLS facilities while exposing owned connection lifetime and backpressure | More adapter code and platform-specific verification; recommended subject to the completion boundary above. |
| Replace the HTTP client with a custom response engine | Direct control of every byte and supported framing | Another security-sensitive parser and compatibility boundary; defer unless the adapter proves infeasible. |
| Raise socket caps or relax cleanup observations | Could reduce immediate refusals | Conceals the ownership problem and changes approved limits; not recommended. |
| Broaden formats or update the player/SDK concurrently | More nominal support | Confounds transport evidence and expands native/device qualification; separate increment. |

Recommended stack: locked Flutter/Dart and video player; small public-API raw transport owners plus SDK HTTP parsing; ordinary TLS verification with the explicitly agreed public completion guarantee; strict generated-HLS projection and metadata admission; actual finite socket/TLS and PostgreSQL/HTTP/FFmpeg/Android fixtures; existing guarded serial builds, reusable compiler/SDK/APKs, private bounded evidence and native-manager artifact retirement. No new resolved dependency or OS change is currently recommended.
