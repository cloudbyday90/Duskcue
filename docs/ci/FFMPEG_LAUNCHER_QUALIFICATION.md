# FFmpeg initial-exec qualification

This is a focused playback-launcher review, not a security scan or complete Linux server qualification. The diagnosed source applied the final filter in `Command.pre_exec`, before initial FFmpeg execution, while omitting `execve` and `execveat` and using `KillProcess` for unmatched calls. The mandatory managed-launch source described below replaces that ordering for both playback and storyboard generation. Current C/Rust library/SQL artifacts compile at `24bcb70`; 25 selected cases pass. The corrected managed-test runtime now exposes actual FFmpeg failure on the traced AMD64 `open` alias after bootstrap acknowledgment. That narrow alias repair is prepared, with Landlock and exec/network denial retained. Complete managed-program/progressive and ARM64 qualification remain open; the kernel reproduction below is historical evidence of the original ordering.

Actual trace: [run 37709091910](https://github.com/cloudbyday90/Duskcue/actions/runs/37709091910/job/113090472769), artifact `11520944049`, retains the 2,446,524-byte producer trace with SHA-256 `cfd77097e7e5a1205e6a6b670a5fc8d854a9be413fdb87344eb9b67afdb84cde`. Lines 37290–37293 show managed PID 64 calling native syscall 2 (`open`) immediately before SIGSYS. The existing filter allows `openat` but omitted `open`. The prepared x86-only alias remains subject to the same [Landlock file rights](https://docs.kernel.org/userspace-api/landlock.html); [open/openat semantics](https://man7.org/linux/man-pages/man2/open.2.html) establish the file-opening relationship. There is no new exec/network permission or path grant. Fresh passing managed output and negative cases must verify this repair; production playlist and rename policy are still unchanged.

## Mandatory managed-launch implementation

The final application filter must continue blocking both execution syscalls before any untrusted media parsing. Classic seccomp filtering is not a mutable one-shot permission; adding an ordinary exec allow rule would also permit later execs. The required change is a trusted initial-execution boundary followed by mandatory filter installation inside the new FFmpeg image before its main routine processes input.

The implementation uses one small Linux bootstrap library required by a dedicated managed FFmpeg executable copy. The existing original FFmpeg/FFprobe binaries and their other callers remain unchanged. The managed copy's mandatory ELF dependency makes a missing bootstrap fail before main; an optional preload that can be ignored is insufficient. Parent preparation supplies the unchanged compiled BPF through a sealed private descriptor. The bootstrap validates the descriptor, installs the final deny-by-default filter, acknowledges success through an owned pipe, closes private descriptors and fails closed on any error. Landlock/no-new-privileges and inherited filtering remain in force through initial trusted loading. The application-facing manager/lifecycle/DTO/auth/profile behavior stays unchanged.

The source is implemented, with scoped Rust formatting and source inspection only. C compilation, Linux Rust compilation, runtime packaging and actual process qualification are pending. There is no new exec or networking allowance. A source comparison confirms the same 62 x86_64 syscall identities. The four unavailable ARM64 legacy names are gated to x86_64; their already allowed modern equivalents remain. ARM64 fadvise uses native number 223 because the locked libc omits its constant, matching the [kernel generic UAPI](https://github.com/torvalds/linux/blob/master/include/uapi/asm-generic/unistd.h). ARM64 compilation/output remains unqualified.

The focused modules are `services/sandbox/{filesystem,filter,wire,descriptors,managed_elf,launch,owned_output}.rs`, `services/transcoding/launcher.rs`, and `native/ffmpeg-bootstrap/bootstrap.c`. No Cargo dependency or workspace addition is needed. Both known sandboxed FFmpeg callers now use the managed preparation and readiness contract; the unused combined pre-exec installation facade was removed after whole-repository caller inspection. Hardware detection, FFprobe, subtitle extraction and other unsandboxed callers continue using the original binaries.

The managed executable is `/usr/local/libexec/duskcue-ffmpeg`, its required absolute ELF dependency is `/usr/local/lib/duskcue-ffmpeg-bootstrap.so`, and its ordered SHA256 manifest is `/usr/local/libexec/duskcue-ffmpeg.sha256`. The parent verifies digests with bounded buffers, direct root-owned files and ancestors without group/world write permission, native ELF64 architecture, a unique mandatory dependency, bootstrap initialization and the expected trusted musl interpreter. Loader environment overrides are removed. Missing/corrupt/untrusted/mismatched files are refused before spawning; no original-binary fallback exists on Linux. Standalone Linux deployments therefore also require these managed runtime files, not merely a bare server binary. Windows retains its existing FFmpeg path. Playback adds `-nostdin` at the command facade to enforce the existing intended noninteractive behavior: locked tokio-process-tools replaces Command stdin-null with its own pipe, so a null setting alone does not establish that behavior. Stream/filter/output choices are unchanged.

The parent compiles the BPF and prepares Landlock before fork. The private policy is a sealed memfd with close-on-exec initially set, an exact versioned 40-byte header and at most 4096 eight-byte instructions. Required seals prohibit writes, growth, shrinking and seal changes; see [Linux memfd](https://www.man7.org/linux/man-pages/man2/memfd_create.2.html) and [file seal semantics](https://www.man7.org/linux/man-pages/man2/F_GET_SEALS.2const.html). Its FNV checksum covers the complete header with the checksum slot zeroed and the BPF payload, detecting corruption within this bounded protocol; the trusted sealed descriptor, not that checksum, establishes policy ownership. Only this child's two private descriptors have close-on-exec cleared. Landlock uses the existing BestEffort ABI-3 request and path rules; no-new-privileges must be confirmed. The raw filesystem status and nonce-owned constructor acknowledgment together form a fixed 40-byte pipe response, with a five-second readiness deadline.

The mandatory constructor validates seals, regular-file/pipe types, exact size, protocol version, native architecture, checksum and no-new-privileges before installing the unchanged final filter. TSYNC must synchronize any dependency-created threads before acknowledgment; a nonzero result fails closed. It removes private environment values and closes descriptors before untrusted parsing. Missing/corrupt descriptors and installation/acknowledgment failure exit before FFmpeg main. Inherited seccomp and Landlock remain present throughout initial trusted loading.

Mandatory dependency loading is essential: an optional preload that can be ignored would not establish this boundary. The dynamic loader and packaged system dependency initialization are trusted code and may run before the bootstrap constructor; they must come from the controlled runtime rather than writable media/cache paths. [Dynamic library initialization](https://man7.org/linux/man-pages/man3/dlopen.3.html) describes initialization before returning to application code, but constructor order across this actual musl/FFmpeg dependency graph still requires artifact proof. TSYNC closes a prior-constructor thread gap; it does not make the earlier trusted loader phase subject to the final application filter.

Playback transfers the handle and capacity permit to the owned worker actor before awaiting readiness. A pending guard signals cancellation if the observer disappears; explicit acknowledgment errors await actual stop and cache cleanup. Preparation errors clean the newly owned cache without a child. The same guard covers the subsequent play-session SQL publication await and disarms after successful publication. Worker retry logic now distinguishes `Completed` from a successful `Timeout` result, so timeout cannot release the physical process or permit.

Storyboard generation preserves arguments and publication behavior, with a focused actor owning its process group and bounded output while the observer waits for mandatory readiness. Errors await physical completion; an abandoned observer removes only its owned output file after termination. A second observer acknowledgment handles cancellation between completion delivery and acceptance. Its pre-existing external advisory transaction can drop before the actor finishes cancellation; another generation may then start with a distinct artifact UUID. The actor prevents late publication from the dropped observer and does not delete another generation's directory. Broader transaction-owned generation and general lost-response database reconciliation are separate concerns, not claimed as solved here.

Source-prepared tests cover bounded policy encoding, seal immutability, complete/partial/missing ACK, nonce/architecture/status refusal, malformed ELF/dependency/constructor/search paths, final exec/network-denial BPF, timeout-as-running, and an opt-in actual managed FFmpeg HLS/physical-release case. The test-only native `probe.c` is never copied into production. A fresh isolated qualification image must link it against the exact production bootstrap with its absolute SONAME, install the root-owned probe at `/usr/local/libexec/duskcue-ffmpeg-probe` and write a separate ordered probe/library SHA256 manifest. Test-only preparation validates that fixed pair; production preparation remains fixed to managed FFmpeg. Ignored probe cases exercise actual constructor fail-closed behavior for missing descriptor and corrupt magic, architecture, length, nonce and payload before a main marker; later exec/socket SIGSYS; owned outside-path EACCES with a readable-before-sandbox control; allowed source/cache; and observer cancellation after stdout EOF with physical `/proc` absence checked after cleanup. Negative probe results demonstrate this actual compiled boundary, while the separate FFmpeg HLS case is required to demonstrate the real production program. None of these new Rust tests has been compiled or run in this checkpoint. The earlier cached Windows executable is stale and must continue refusing current source mismatches.

Required proof after a fresh guarded Linux artifact exists: execute the actual production launcher, observe bootstrap/enforced-or-degraded status and real FFmpeg progress/output, verify owned source/cache access and denied outside paths, confirm later exec/network attempts stay denied, and await the owned worker's physical release. Then run actual mapped/default/selected-caption output, profile/session binding and stop/seek integration through that launcher. A copied policy, raw Docker FFmpeg or historical image cannot replace that qualification.

The later [source readiness checkpoint](FFMPEG_LAUNCH_READINESS.md) records exact normal-guarded Windows selectors and fresh Linux artifact requirements. Managed FFmpeg output is now split into finite completed VOD and separately throttled active-worker/PID cancellation cases: ten units plus five ignored Linux runtime cases are prepared, all uncompiled/unrun. It also records the existing VOD publication delay and the required progressive EVENT/readiness/runtime/atomic-rename proof. Production playlist mode and final filter remain unchanged. Current whole Rust formatting passes; Docker Cargo now explicitly uses two jobs, without a current image build or runtime pass.
