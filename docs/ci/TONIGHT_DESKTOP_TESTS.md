## Research and isolation decision

Reviewed official documentation October 7, 2026. [Playwright's WebView2 guide](https://playwright.dev/docs/webview2) supports attaching to the native application's WebView2 over CDP, using `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` and a separate `WEBVIEW2_USER_DATA_FOLDER`. The runner sets these only on its child process and chooses an unused loopback CDP port. [Microsoft's WebView2 data-folder guidance](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder) explains that this folder contains browser state; isolating it prevents reuse of the normal desktop browser profile.

The application also stores `server-connections.json` through Tauri's `app_data_dir`. WebView2 isolation alone does not isolate that native file. [Tauri configuration](https://v2.tauri.app/reference/config/#identifier) defines the application identifier's system identity. The installed Tauri version resolves its application data through Windows known folders and the compiled identifier. Changing an `APPDATA` environment value alone is insufficient. Therefore the test builds the same actual sources using a generated, unique identifier, a distinct product/binary name, and no installer. The newer official `appDirectoriesOverride` option is absent from the installed CLI schema; this runner does not assume support for it.

The native normalizer currently accepts only the public Duskcue port, 48027. The fixture binds two generated `127.x.x.x:48027` addresses for connection and switching checks. Binding failure stops the test; the runner does not terminate existing listeners or substitute the internal API port. The real native `reqwest` health check reaches `/health/ready` on those listeners. Frontend fixture requests are intercepted by Playwright and must use one of the selected test origins.

The native keyring service is still `com.duskcue.desktop`, irrespective of test identifier. Test origins are unique, and the runner requires both credential lookups to be empty before login. It uses synthetic credentials and tokens, verifies the real keyring round trip, and deletes only a token that exactly matches the token it generated for that origin. An unexpected credential is left untouched and reported as a failure. Tokens and passwords are omitted from result logs and native connection files. Shared web-fixture user/device seeding is suppressed: the actual desktop auth cache and device-identity service establish state, and the generated device identity must survive reload and server switching.

Actual 400% browser zoom is also prepared. The installed `@tauri-apps/api` 2.11.1 [Webview.setZoom API](https://v2.tauri.app/reference/javascript/api/namespacewebview/#setzoom) invokes `plugin:webview|set_webview_zoom` with `{ label, value }`.
